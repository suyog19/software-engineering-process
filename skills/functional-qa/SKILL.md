# Functional QA

Use the accepted issue, exact finished revision, and available test evidence. Verify each acceptance criterion, happy paths, relevant edge cases, validation/errors, and state transitions. Do not rely on the implementer's claims. Distinguish blocking defects from suggestions.

Emit `functional-qa-verdict/v1` evidence bound to the exact SHA, with pass/fail, findings, coverage limitations, and residual functional risk.
