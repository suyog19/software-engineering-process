# Independent review

Start in a fresh review context with read-only access to the completed change, issue, resolved obligations, and evidence. Do not inherit implementation reasoning as trusted fact. Review correctness, scope, contracts, tests, controls, evidence consistency, and material maintainability risks.

The producer context ID must differ from the implementation context ID and `freshContext` must be true. A different vendor is optional diversity, not proof of independence. Emit exact-revision `independent-review/v1` evidence.
