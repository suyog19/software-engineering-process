# Architecture review

Use only when selected. Review requirements, repository constraints, existing architecture, material risks, public contracts, and alternatives. Prefer existing, local, reversible patterns. Challenge new frameworks, services, dependencies, one-use abstractions, and speculative configurability.

Record the minimum sufficient decision, constraints, alternatives rejected, consequences, and residual risks as exact-revision `architecture-decision/v1` evidence. Correctness, locked controls, and Protected assurance remain mandatory.
